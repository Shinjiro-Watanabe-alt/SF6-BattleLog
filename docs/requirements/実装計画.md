# SF6-BattleLog 実装計画

## 0. 文書について

本書は時系列追記型の開発記録である。各開発ラウンドで経緯、調査、設計判断、検証、未解決事項を追記し、過去の判断は書き換えない。

## 1. 全体の進め方

1. ユーザーの要望を受け入れ条件へ整理する。
2. 現在のコードと3点セットを確認し、設計判断を合意する。
3. 作業ブランチでコード、要件定義書、実装計画、テスト仕様書を同時更新する。
4. 静的チェックと実機確認項目を実施し、未解決を含めて報告する。
5. ユーザーの明示承認後にPRを作成し、Merge Commit方式で`main`へ統合する。

## 2. 開発環境構築

- 公開: GitHub Pages。`workflow_dispatch`でのみ公開する。
- 実装: リポジトリ直下の静的PWA。
- 保存: IndexedDB `ed-match-note`。既存の`matches`ストアと動画用`videos`ストアを使用する。
- 実機: AndroidのChromeまたはPWA。データは端末・ブラウザごとに保存される。

## 3. テスト戦略

- ロジック: Node.jsの構文確認、データ形式の入力制約、既存JSONとの互換性を確認する。
- 画面: Android実機で入力・保存・再読込・JSON取込・YouTube遷移を確認する。
- 公開: GitHub Actionsの成功とGitHub Pages上での更新を確認する。

## 4. 2026-09-11: ドキュメント基盤と重要局面機能の設計

### 4.1 経緯

1. 日次のYouTube限定公開動画を分析し、セットごとの改善ポイントを後から参照したい。
2. 勝敗を分けた局面、再現したい勝ち筋、繰り返す失点をタイムスタンプで蓄積したい。
3. 今後の追加・改修で必ず要件定義書、実装計画、テスト仕様書を更新する運用にしたい。
4. Guildリポジトリの`codex/additional-develop`にあるテンプレートと開発規範を踏襲したい。

### 4.2 調査

- Guildの`AGENTS.md`、`CLAUDE.md`、3点セットのテンプレート、開発・GitHub・Codex運用ガイドを参照した。
- SF6-BattleLogはビルド工程を持たない静的PWAであり、GuildのFlutter固有ルールは適用しない。
- 現状は動画ログ、セット範囲、JSON取込まで実装済みであり、重要局面を保存・表示・再生するUIは未実装である。

### 4.3 設計判断

- 採用: 1セット最大5件の重要局面を、時間・局面・評価・内容・次回の行動で持つ。
- 採用: 初期版はYouTubeを新しいタブで該当秒数から開く。動画埋込みは行わない。
- 採用: 3点セットと`AGENTS.md`／`CLAUDE.md`をリポジトリへ追加し、コード変更時の同時更新を必須化する。
- 非採用: 全ラウンドの全イベントを記録する方式。入力・分析の負担が高く、振り返りが続かないため。
- 非採用: この時点での独立`milestones`ストア。Phase 2の横断検索仕様が未確定のため、初期実装では`Match`内の配列として開始し、必要時に移行する。
- 非採用: YouTube iframe埋込み。限定公開動画の視聴可否、モバイル表示、広告・ログイン状態の影響を初期版で抱えないため。

### 4.4 実装体制

- ドキュメントと設計判断はメイン担当が直接作成する。会話・過去判断に依存するため、機械的な委任対象にしない。
- 重要局面UIの実装は本ラウンドのドキュメント整備後に着手する。
