# SF6-BattleLog 実装計画

## 0. 文書について

本書は時系列追記型の開発記録である。各開発ラウンドで経緯、調査、設計判断、検証、未解決事項を追記し、過去の判断は書き換えない。

## 1. 全体の進め方

1. ユーザーの要望を受け入れ条件へ整理する。
2. 現在のコードと3点セットを確認し、設計判断を合意する。
3. 作業ブランチでコード、要件定義書、実装計画、テスト仕様書を同時更新する。
4. 静的チェックと実機確認項目を実施し、未解決を含めて報告する。
5. ユーザーの明示承認後にPRを作成し、Merge Commit方式で`main`へ統合する。

## 2. 開発環境構築

- 公開: GitHub Pages。`workflow_dispatch`でのみ公開する。
- 実装: リポジトリ直下の静的PWA。
- 保存: IndexedDB `ed-match-note`。既存の`matches`ストアと動画用`videos`ストアを使用する。
- 実機: AndroidのChromeまたはPWA。データは端末・ブラウザごとに保存される。

## 3. テスト戦略

- ロジック: Node.jsの構文確認、データ形式の入力制約、既存JSONとの互換性を確認する。
- 画面: Android実機で入力・保存・再読込・JSON取込・YouTube遷移を確認する。
- 公開: GitHub Actionsの成功とGitHub Pages上での更新を確認する。

### 4.2 調査

- Guildの`AGENTS.md`、`CLAUDE.md`、3点セットのテンプレート、開発・GitHub・Codex運用ガイドを参照した。
- SF6-BattleLogはビルド工程を持たない静的PWAであり、GuildのFlutter固有ルールは適用しない。
- 現状は動画ログ、セット範囲、JSON取込まで実装済みであり、重要局面を保存・表示・再生するUIは未実装である。

### 4.3 設計判断

- 採用: 1セット最大5件の重要局面を、時間・局面・評価・内容・次回の行動で持つ。
- 採用: 初期版はYouTubeを新しいタブで該当秒数から開く。動画埋込みは行わない。
- 採用: 3点セットと`AGENTS.md`／`CLAUDE.md`をリポジトリへ追加し、コード変更時の同時更新を必須化する。
- 非採用: 全ラウンドの全イベントを記録する方式。入力・分析の負担が高く、振り返りが続かないため。
- 非採用: この時点での独立`milestones`ストア。Phase 2の横断検索仕様が未確定のため、初期実装では`Match`内の配列として開始し、必要時に移行する。
- 非採用: YouTube iframe埋込み。限定公開動画の視聴可否、モバイル表示、広告・ログイン状態の影響を初期版で抱えないため。

### 4.4 実装体制

## 5. 2026-09-11: 重要局面タイムラインの実装

### 5.1 実装内容

- 最近の対戦からセット詳細を開き、重要局面を最大5件まで追加・編集・削除できるようにする。
- 重要局面は、動画内時間、局面、評価、起きたこと、次回の行動、方針、見直し状況を保存する。
- 動画ログが紐付いたセットでは、時刻ボタンからYouTubeを秒数指定で新しいタブに開く。未紐付けでは遷移を無効化して案内を表示する。
- 新規セットに空の`milestones`配列を持たせ、旧セットは配列がない状態のまま互換表示する。
- JSONスキーマを3へ上げ、テンプレートには重要局面の例を含める。旧スキーマのJSONも`milestones`未指定として取り込める。

### 5.2 設計判断

- 追加・編集はセット詳細画面から行う。対戦直後の基本入力を重くせず、動画分析時に必要な情報だけを入力できるため。
- 初期版でも編集・削除を含める。分析の解釈や練習状況は後から変わるため、固定データにしない。
- IndexedDBのストア追加は行わない。`matches`の任意フィールドなので、既存データのスキーマ移行は不要である。

### 5.3 検証・未解決事項

- 静的確認とJSON形式の確認を本ラウンドで行う。
- Android実機でのダイアログ操作、YouTubeの時刻遷移、PWA更新は公開後に確認する。
- 横断検索・重要局面からの傾向集計はPhase 2として見送る。

## 6. 2026-09-11: 動画中心のホームと分析依頼導線

### 6.1 実装内容

- 起動画面の最上部を日別動画カード一覧へ変更し、日付順で日ごとの分析サマリーを表示する。
- 動画詳細画面を追加し、日別サマリー、紐付くセット、セット追加、YouTube遷移をまとめる。
- 動画詳細に`分析を依頼`、`依頼文をコピー`、`分析JSONの雛形`を追加する。
- 分析依頼はWeb Share APIを優先し、利用できない環境ではクリップボードへコピーする。アプリから外部サービスへ自動送信しない。

### 6.2 設計判断

- 日別動画を主画面の先頭に置く。PS5録画を日次のYouTube限定公開動画として扱う運用と、セット・重要局面の振り返り単位を一致させるため。
- 「動画アップロード」はGitHub Pages上のファイルアップロードではなく、YouTube限定公開URLの登録として実装する。動画保存用サーバーがなく、GitHubへ動画を置かない制約に合うため。
- ChatGPTへの依頼は共有シートまたはコピーに留める。APIキーや認証情報を静的サイトに持たず、限定公開URLをユーザーの明示操作でのみ共有するため。

### 6.3 検証・未解決事項

- 静的確認とJSON雛形の構造確認を実施する。
- Android実機で共有シートにChatGPTが表示されるかは端末・アプリ側の共有対応に依存するため、公開後に確認する。
- 共有先を直接ChatGPTへ固定するディープリンクは実装しない。アプリやブラウザの対応差が大きく、共有シートの方が安定するため。
